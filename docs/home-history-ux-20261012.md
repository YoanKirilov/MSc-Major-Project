# Home and saved-report usability — 12 October 2026

## Scope and execution plan

1. Show saved reports in small batches. Append another batch when the reader scrolls
   to the end; do not fetch the whole library automatically on page opening. Keep
   an explicit keyboard-operable load control, accurate counts, search/filter reset,
   retryable errors and the already rendered reports.
2. Consolidate scan setup on the home page. Remove the duplicate links to separate
   Light/Deep pages, but retain both modes and the existing compatibility routes.
   Preserve explicit scan admission, target validation, refresh recovery and parallel
   jobs. Merely opening a page or changing a mode must never start a scan.
3. Put target selection, readiness, the authorisation reminder and one primary Scan
   action together. Shorten the introduction and move detailed coverage/timing into
   an optional disclosure, without deleting safety information.
4. Check bounded loading, failures/races, keyboard focus, narrow/enlarged text and
   desktop layout using synthetic reports. Run offline checks and responsive browser
   checks; do not launch Nmap, AI processing or external enrichment for this UI task.

Existing local reports and unrelated changes are preserved. This record does not
claim a live network assessment, physical-phone or participant evaluation.

## Design references

The primary action stays with its setup and uses a clear action label; duplicate
primary actions are avoided. [GOV.UK button guidance](https://design-system.service.gov.uk/components/button/).
Loading/count/error feedback is conveyed through a concise status region rather
than moving focus for every update. [W3C status-message guidance](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html).
Controls and text must reflow on narrow and enlarged layouts without losing access.
[W3C reflow guidance](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html).

This is a native report list with an explicit load control, not an ARIA feed. No
entry is removed merely because it has scrolled out of view; navigation and storage
help remain available. Animations are not needed to reveal readable report links.

## Implemented behaviour

- Home: one scan-choice fieldset and setup card, clear readiness/permission feedback
  directly above a full-width Scan button, and optional technical coverage below.
  Both scan modes and target/recovery/cancellation controls remain. `/light` and
  `/deep` are compatibility entry points, not duplicate links on the home page.
- Saved reports: eight initial entries and eight per subsequent request. Downward
  wheel/touch/key scrolling near the list end requests another batch. Initial
  layout, resizing, programmatic scrolling and focus changes do not drain history.
  A native Load more button also works without an observer; native scrollbar-drag
  event behaviour varies by browser, so this is the reliable alternative there.
- Automatic append leaves focus alone. Explicit Load more/retry/refresh moves focus
  to the first newly available report. Previously loaded links stay readable; no
  fading, virtualization or disappearing report entries are introduced.
- Search/filter submissions reset pagination using a snapshot. An unsubmitted input
  edit does not silently change later batches. Late responses cannot replace newer
  results; failed requests preserve visible entries and can retry the same offset.
  Duplicates/changed totals or an unexpectedly empty page produce an honest notice
  and refresh option rather than claiming that every match was displayed.
- The existing API still searches the full JSON library before pagination. This
  change bounds frontend batches, not the library's overall matching work or the
  total number of reports a reader may choose to load. No database was introduced.

New tests are `tests/history_ui.test.mjs`,
`tests/browser_test_history_scroll.py` and the two home-setup cases in
`tests/browser_test_ui_ux.py`; the repeatable check runner includes the new JS suite.
The installed-package check must include `static/js/history-feed.mjs`.
